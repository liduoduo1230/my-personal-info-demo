# 员工个人信息修改 Demo 设计

## 目标与范围

制作一个移动端 H5 可交互 Demo，让员工查看并修改个人资料，演示即时保存、提交审核、审核中撤回、审核通过与审核驳回的完整交互。Demo 使用前端本地模拟数据，不接登录、文件存储、审批或员工主数据接口。

首版覆盖六类信息：个人基本信息、教育信息、家庭信息、外部工作经历、银行卡信息、紧急联系人。不提供修改前后内容对比，不在列表或详情中显示“直接生效 / 需审核”标签。

## 业务规则

### 审核范围

- 个人基本信息拆分为两个编辑流程：身份信息（姓名、证件类型、身份证号）修改需审核；联系信息（性别、手机号、邮箱、现居住地址）保存后直接生效。详情页逐字段展示，点击字段进入对应表单。
- 教育信息：新增、修改和删除均需审核。
- 外部工作经历：新增、修改和删除均需审核。
- 银行卡信息：新增、修改和删除均需审核。
- 家庭信息：保存后直接生效。
- 紧急联系人：修改需审核。

### 材料要求

- 修改姓名或身份证相关信息时，必须上传身份证或其他有效证明材料。
- 修改姓名时，额外提示员工自行核实发薪银行卡户名是否需要同步修改。
- 修改学历信息时，必须上传学信网材料、毕业证书或其他学历证明。
- 修改外部工作经历时，必须上传简历。
- 材料缺失时阻止提交，并在对应上传区域显示明确错误文案。

### 按钮与生效

- 当前修改不涉及审核字段时，底部主按钮显示“保存”；成功后数据立即更新。
- 当前修改涉及任一审核字段时，底部主按钮显示“提交审核”；提交成功后显示本次修改后的信息，并标记“待审核”。
- 同一信息分类待审核期间不可再次编辑或重复提交，仅提供“撤回申请”。
- 撤回成功后恢复审核前的信息，清除待审核状态，并允许重新编辑。
- 审核通过后，修改后的信息成为正式信息，取消状态提示。
- 审核驳回后，恢复修改前的信息，并显示驳回原因。

## 页面与交互

### 信息总览

首页为纵向完整资料页，顶部展示员工头像、姓名和编号，下方直接依次展示个人基本信息全部字段、全部教育经历、全部家庭成员、全部工作履历、银行卡和紧急联系人。不设置六个分类入口或中间详情页。字段编辑、记录编辑、新增、审核状态和撤回操作均直接位于对应模块；编辑表单使用独立页面，完成后返回完整资料首页。

### 分类详情与编辑

详情页展示该分类的当前可见数据及编辑入口。普通状态可进入表单；待审核状态下表单只读，展示修改后的信息、提交时间和“撤回申请”。已驳回状态展示恢复后的原信息及驳回原因，并允许再次编辑。

教育、家庭、工作经历采用逐条记录列表，每条展示完整信息和独立“编辑”按钮，模块提供新增入口。编辑页支持删除。教育与工作经历的新增、编辑、删除走审核；家庭信息的新增、编辑、删除保存后直接生效。新增记录被驳回后不显示，删除申请被驳回后原记录继续显示。

银行卡信息和紧急联系人均在详情中展示独立“编辑”按钮，修改后提交审核。

### 文件上传

使用移动端上传触发器和文件列表，展示文件名、类型、上传状态、删除或重试操作。Demo 模拟选择文件、上传中、成功和失败状态，不读取或上传真实文件内容。

### 状态演示

Demo 提供轻量的“演示控制”入口，可将待审核申请切换为审核通过或审核驳回，用于验证不同状态。该入口明确标注为 Demo 能力，不属于正式员工端产品功能。

## 数据状态模型

每个信息分类维护 `approvedData`、可选的 `pendingData`、`status` 和可选的 `rejectReason`。`status` 取值为 `normal`、`pending`、`rejected`。

- 提交审核：保留 `approvedData`，写入 `pendingData`，页面读取 `pendingData`。
- 撤回：删除 `pendingData`，页面重新读取 `approvedData`。
- 通过：以 `pendingData` 覆盖 `approvedData`，清除流程状态。
- 驳回：删除 `pendingData`，页面读取 `approvedData`，保留驳回原因供提示。
- 直接保存：立即覆盖 `approvedData`。

状态不能只依赖颜色表达，必须同时提供状态文字；待审核期间编辑与提交控件应呈禁用或隐藏状态，并说明不可操作原因。

## 视觉与组件规范

- 平台为移动端 `[M]`，基准画布宽度 `375px`，主内容容器 `343px`，左右边距 `16px`。
- 页面使用暖灰 `#F7F6F3`，卡片使用白色，主文字使用沃野 `#3B3431`，月晖金仅用于克制强调。
- 卡片圆角 `12px`，内部间距采用 `12px / 16px`；正文使用移动端 `14/22`，标题使用 `16/24`。
- 复用移动端导航、列表、输入、按钮、上传、文件列表、Notice、Toast、Dialog 等语义组件。
- 底部操作区固定并预留安全区；所有触控热区不小于 `44 × 44px`。
- 待审核使用状态文字配合暖色提示；错误和驳回使用危险色、图标和文字共同表达。
- 响应式以 375px 为基准，在更宽屏幕居中显示，内容最大宽度保持移动端阅读尺度。

## 异常与边界状态

- 表单包含必填校验、格式校验、材料缺失和上传失败反馈。
- 保存、提交、撤回均模拟加载态，操作期间按钮禁用以避免重复请求。
- 提供数据加载骨架、空列表、加载失败、离线和无权限状态的 Demo 表现。
- 撤回前使用确认弹窗，明确撤回后将恢复审核前信息。
- 本地刷新后保留演示数据；提供“重置 Demo 数据”能力恢复初始状态。

## 验收场景

1. 修改紧急联系人并保存，首页立即显示新信息。
2. 仅修改普通基本信息时按钮为“保存”，保存后立即生效。
3. 修改姓名但未上传证明时无法提交；上传后按钮为“提交审核”，并出现银行卡户名核实提示。
4. 提交学历或工作经历修改时分别校验学历证明和简历。
5. 提交银行卡修改后展示新银行卡信息和“待审核”，不能再次编辑或提交。
6. 撤回待审核申请后恢复原信息，并可重新编辑。
7. 模拟审核通过后新信息正式生效且状态消失。
8. 模拟审核驳回后恢复原信息，并展示驳回原因。

## Demo 技术边界

Demo 为单端前端实现，业务数据和流程变化存放于浏览器本地。证明材料仅保存模拟文件元信息，不持久化真实文件。正式落地时需由后端负责权限、敏感字段加密与脱敏、文件安全、审批幂等、审计记录以及员工主数据同步。

## 后台审核工作台 Demo

新增 PC 端员工信息审核工作台，采用列表与右侧抽屉结构。统一审核单覆盖个人身份、银行卡、紧急联系人等模块级申请，以及教育、工作履历、子女家庭信息等记录级新增、修改和删除申请。每张申请只允许整单通过或整单驳回，不支持字段级部分通过。

页面提供待审核、已通过、已驳回统计，支持按员工姓名/花名、信息模块、操作类型和状态筛选。表格展示申请单号、员工、部门、模块、操作类型、提交时间和状态。点击行打开右侧抽屉；修改申请展示原信息和申请信息，新增申请展示新增内容，删除申请展示拟删除记录，同时展示证明材料。

抽屉底部固定“驳回”和“通过”。驳回必须填写原因并二次确认，通过需要二次确认。处理完成后刷新统计与列表，自动打开下一条待审核单；没有下一条时关闭抽屉并提示待审核申请已处理完。员工撤回导致当前申请失效时，提示申请已撤回并自动打开下一条。
