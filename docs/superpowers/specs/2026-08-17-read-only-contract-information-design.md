# 只读合同信息模块设计

## 目标

在员工端 `my personal info` 首页增加“合同信息”模块，让员工查看当前合同资料。合同信息由其他人事系统维护，本页面不允许新增、编辑、删除，也不进入员工信息审核流程。

## 页面与位置

- 平台：移动端。
- 基准画布宽度：`375px`。
- 主内容容器宽度：`343px`，左右边距各 `16px`。
- 首页模块顺序调整为：个人基本信息、银行卡、证书、教育、履历、合同信息、家庭信息、紧急联系人。
- 顶部信息锚点同步增加“合同”，位置与首页模块一致。

## 展示内容

合同信息使用与个人基本信息、银行卡和紧急联系人一致的字段列表样式，展示以下字段：

- 合同类型
- 合同主体
- 合同开始日期
- 合同结束日期
- 合同状态

Demo 默认展示一份有效合同。任一字段无数据时显示 `—`，不隐藏字段，保证信息结构稳定。

## 交互约束

- 模块标题行不显示编辑笔图标。
- 模块和字段行均不提供点击跳转。
- 不显示新增、删除、保存、提交审核、待审核或撤回入口。
- 合同数据不加入可编辑字段映射、提交事件和审核列表。
- 页面现有其他模块的编辑与审核行为保持不变。

## 视觉与可访问性

- 复用现有移动端白色模块、字段行、分隔线、字号和间距，不新增装饰性卡片样式。
- 主文字和辅助文字沿用现有品牌色与文本层级。
- 合同状态以普通文本展示，不仅依赖颜色表达。
- 因模块完全只读，不渲染无效或禁用态按钮，避免误导用户。

## 数据与兼容

- 初始状态新增独立 `contract` 数据段，仅存放已生效的只读合同数据。
- 旧版浏览器本地数据缺少 `contract` 时，加载阶段补齐默认合同数据，避免页面空白或运行错误。
- 重置 Demo 数据后恢复默认合同数据。

## 测试范围

- 验证初始状态包含合同信息及五个约定字段。
- 验证首页模块和顶部锚点均按约定顺序包含合同信息。
- 验证合同模块展示字段值且不包含编辑、新增、删除或审核操作。
- 运行 JavaScript 语法检查、完整自动化测试和 Git 差异格式检查。
